
## 1. Основные понятия React

### Функциональные компоненты

В React компоненты представляют собой изолированные, переиспользуемые части пользовательского интерфейса. В нашем проекте все компоненты созданы как функциональные, то есть это обычные функции, принимающие пропсы (свойства) и возвращающие JSX-разметку.

Пример простого функционального компонента:

```tsx
// Display.tsx
import React from 'react';

type DisplayProps = {
  input: string;
  result: string;
};

export default function Display({ input, result }: DisplayProps) {
  return (
    <div className="display">
      <div className="display-input">{input || '0'}</div>
      <div className="display-result">{result}</div>
    </div>
  );
}
```

**Объяснение:**  
- **Типизация пропсов:** Мы описали типы для пропсов с помощью TypeScript. Это помогает избежать ошибок и улучшает автодополнение в редакторе.
- **JSX-разметка:** Функция возвращает HTML-подобную разметку, которая описывает, как должен выглядеть компонент на странице.

### Состояние (State) и хуки

В функциональных компонентах состояние хранится с помощью хука `useState`. Оно позволяет компоненту реагировать на изменения и перерисовываться.

Пример использования `useState` в компоненте-калькуляторе:

```tsx
// Calculator.tsx (фрагмент)
const [input, setInput] = useState<string>('');
const [result, setResult] = useState<string>('');
const [history, setHistory] = useState<string[]>([]);
const [theme, setTheme] = useState<'light' | 'dark'>('light');
```

**Объяснение:**  
- **`useState`** – позволяет задать начальное значение состояния и получить функцию для его обновления.
- Каждый вызов `useState` возвращает массив с двумя элементами: значение и функцию для его изменения.  
- Типизация состояния (например, `string` или массив строк) помогает разработчику работать с данными корректно.

### Эффекты (useEffect)

Хук `useEffect` используется для выполнения побочных эффектов, например, для подписки на события или работы с API. В нашем проекте он используется для обработки событий клавиатуры.

Пример:

```tsx
// Calculator.tsx (фрагмент)
useEffect(() => {
  const handleKeyDownWindow = (e: KeyboardEvent) => {
    if (e.key === ' ') { // Игнорируем пробел
      e.preventDefault();
      return;
    }
    if (/^[0-9+\-*/.]$/.test(e.key)) {
      setInput(prev => prev + e.key);
    } else if (e.key === 'Backspace') {
      setInput(prev => prev.slice(0, -1));
    } else if (e.key === 'Enter') {
      calculateResult();
    }
  };

  window.addEventListener('keydown', handleKeyDownWindow as any);
  return () => window.removeEventListener('keydown', handleKeyDownWindow as any);
}, [input, history]);
```

**Объяснение:**  
- **Подписка на события:** При монтировании компонента добавляется глобальный обработчик событий клавиатуры.
- **Очистка эффекта:** Функция очистки (return callback) удаляет обработчик при размонтировании компонента, чтобы не создавать утечки памяти.
- **Зависимости эффекта:** Массив зависимостей `[input, history]` определяет, когда эффект должен обновляться.

## 2. Организация кода: Компонентный подход

### Разделение ответственности

Код разбит на отдельные компоненты, где каждый отвечает за свою часть функционала:
- **Display:** отвечает за отображение текущего ввода и результата.
- **Button:** отвечает за рендеринг кнопок и обработку кликов.
- **History:** отображает историю вычислений.
- **Calculator:** объединяет все компоненты и содержит основную логику (вычисления, переключение темы, обработка клавиатуры).

### Пример компонента Button

```tsx
// Button.tsx
import React from 'react';

type ButtonProps = {
  value: string;
  onClick: (value: string) => void;
};

export default function Button({ value, onClick }: ButtonProps) {
  return (
    <button
      className="calc-button"
      onMouseDown={(e) => e.preventDefault()}  // Предотвращает фокусировку при клике
      onClick={() => onClick(value)}
    >
      {value}
    </button>
  );
}
```

**Объяснение:**  
- **События:** Обработчик `onMouseDown` предотвращает появление стандартного фокуса, что важно для чистого пользовательского интерфейса.
- **Передача пропсов:** Компонент принимает значение кнопки и функцию обратного вызова, что делает его гибким и переиспользуемым.

## 3. Обработка пользовательского ввода и вычисления

### Логика обработки ввода

В компоненте Calculator реализована логика, которая обновляет состояние в зависимости от действий пользователя (нажатие кнопок или клавиш).

```tsx
// Calculator.tsx (фрагмент)
const handleButtonClick = (value: string) => {
  if (value === 'C') {
    setInput('');
    setResult('');
  } else if (value === '⌫') {
    setInput(input.slice(0, -1));
  } else if (value === '=') {
    calculateResult();
  } else {
    // Предотвращаем некорректный ввод: если поле пустое и нажата "0", ничего не делаем
    if (input === '' && value === '0') return;
    setInput(input + value);
  }
};
```

**Объяснение:**  
- **Условия:** При нажатии кнопки "C" происходит сброс ввода, а кнопка "⌫" удаляет последний символ.
- **Динамическое обновление состояния:** При добавлении символов к строке ввода вызывается функция `setInput`, что приводит к перерисовке компонента с обновленным значением.
- **Обработка пустого ввода:** Если ввод пуст или равен "0", вычисление не запускается, что предотвращает ошибки.

### Вычисление результата

При нажатии кнопки "=" вызывается функция, которая проверяет корректность ввода и вычисляет результат.

```tsx
// Calculator.tsx (фрагмент)
const calculateResult = () => {
  if (input.trim() === '' || input.trim() === '0') {
    return;
  }
  try {
    if (/\/0(?!\.)/.test(input)) {
      setResult('Ошибка: Деление на ноль');
      return;
    }
    const evalResult = eval(input);
    setResult(evalResult.toString());
    setHistory([...history, `${input} = ${evalResult}`]);
    setInput('');
  } catch (error) {
    setResult(`Ошибка: ${error}`);
  }
};
```

**Объяснение:**  
- **Проверки перед вычислением:** Функция сначала проверяет, что строка не пуста и не равна "0".
- **Проверка деления на ноль:** Регулярное выражение `/\/0(?!\.)/` ищет деление на ноль, чтобы вывести сообщение об ошибке.
- **Использование eval:** Функция `eval` вычисляет математическое выражение. (В реальных приложениях лучше использовать безопасные парсеры выражений.)
- **Обновление истории:** После успешного вычисления результат добавляется в историю.

## 4. Стилизация и темы оформления

### Применение CSS для темизации

Стили задаются через CSS, где используются классы для светлой и тёмной тем. Переключение темы происходит путем изменения класса основного контейнера.

Пример CSS-правил:

```css
/* Темы оформления */
.calculator-container.light {
  background-color: #ffffff;
  color: #000;
  border-color: #ccc;
}

.calculator-container.dark {
  background-color: #333;
  color: #fff;
  border-color: #555;
}
```

**Объяснение:**  
- **CSS-классы:** Разные классы определяют разные наборы стилей для тем. При переключении темы меняется класс контейнера, что автоматически применяет нужные цвета и стили.
- **Плавные переходы:** Свойства `transition` обеспечивают плавное изменение фона, цвета и границ.

### Предотвращение "залипания" кнопок

Чтобы кнопки не оставались в активном состоянии (например, при клике мышью или нажатии пробела на клавиатуре), в компоненте Button добавлен обработчик onMouseDown, а в глобальном обработчике клавиатуры – проверка на пробел.

```tsx
// Button.tsx (фрагмент)
onMouseDown={(e) => e.preventDefault()}
```

и

```tsx
// Calculator.tsx (фрагмент в useEffect)
if (e.key === ' ') {
  e.preventDefault();
  return;
}
```

**Объяснение:**  
- **onMouseDown:** Предотвращает получение фокуса кнопкой при клике, что устраняет визуальный эффект "залипания".
- **Проверка клавиш:** Игнорирование пробела предотвращает случайные нажатия, которые могут изменить ввод.

## React

- **Определение:** Библиотека JavaScript для создания пользовательских интерфейсов.
- **Особенности:** 
  - Позволяет строить UI с помощью компонентов.
  - Обеспечивает эффективное обновление DOM с помощью виртуального DOM.
- **Применение:** Создание интерактивных веб-приложений.

---

## JSX

- **Определение:** Расширение синтаксиса JavaScript, позволяющее писать HTML-подобный код внутри JavaScript.
- **Особенности:** 
  - Упрощает создание React-компонентов.
  - Преобразуется в чистый JavaScript с помощью Babel.
- **Применение:** Описание UI в виде декларативного кода.

---

## Babel

- **Определение:** Транспилер для преобразования современного JavaScript (и JSX) в код, поддерживаемый старыми браузерами.
- **Особенности:** 
  - Позволяет использовать новые возможности языка.
  - Конфигурируется с помощью `.babelrc` или других конфигурационных файлов.
- **Применение:** Компиляция JSX и ES6+ кода в ES5 для кроссбраузерной совместимости.

---

## SPA (Single Page Application)

- **Определение:** Одностраничное приложение, где все содержимое загружается на одной странице, а переходы между «страницами» происходят без перезагрузки.
- **Особенности:** 
  - Улучшенный пользовательский опыт за счёт плавных переходов.
  - Меньшее количество запросов к серверу.
- **Применение:** Построение динамичных, отзывчивых веб-приложений.

---

## Рендеринг

- **Определение:** Процесс отображения UI-компонентов в браузере.
- **Особенности:** 
  - React использует виртуальный DOM для оптимизации рендеринга.
  - При изменении состояния компонента происходит повторный рендер только изменённых частей.
- **Применение:** Обновление пользовательского интерфейса при изменении данных.

---

## Компоненты

- **Определение:** Независимые, переиспользуемые блоки кода, которые инкапсулируют логику и представление.
- **Особенности:** 
  - Могут быть функциональными или классовыми.
  - Разбивают сложный UI на небольшие части.
- **Применение:** Структурирование приложения в модульные блоки.

---

## Пропсы (Props)

- **Определение:** Свойства, передаваемые от родительского компонента к дочернему.
- **Особенности:** 
  - Являются неизменяемыми (read-only).
  - Используются для конфигурации и передачи данных.
- **Применение:** Передача информации и вызов обратных функций между компонентами.

---

## Состояние (State)

- **Определение:** Локальные данные компонента, которые могут изменяться в процессе работы приложения.
- **Особенности:** 
  - Изменение состояния приводит к повторному рендерингу компонента.
  - Управляется с помощью хука `useState` в функциональных компонентах или `this.state` в классовых.
- **Применение:** Хранение динамических данных, которые влияют на отображение UI.

---

## Жизненный цикл компонента

- **Определение:** Набор этапов от создания до удаления компонента.
- **Особенности:** 
  - В классовых компонентах используются методы жизненного цикла (например, `componentDidMount`, `componentDidUpdate`).
  - В функциональных компонентах аналогичные эффекты достигаются с помощью хука `useEffect`.
- **Применение:** Выполнение побочных эффектов, настройка подписок, очистка ресурсов.

---

## Принцип единственной ответственности (Single Responsibility Principle)

- **Определение:** Принцип, согласно которому каждый компонент или функция должна выполнять только одну задачу.
- **Особенности:** 
  - Облегчает поддержку и тестирование кода.
  - Способствует переиспользованию компонентов.
- **Применение:** Разделение логики на небольшие, независимые части.

---

## Односторонний поток данных (One-way Data Flow)

- **Определение:** Модель, при которой данные передаются от родительских компонентов к дочерним через пропсы, а изменения состояния инициируются в родительском компоненте.
- **Особенности:** 
  - Обеспечивает предсказуемость и простоту отладки.
  - Изменения в состоянии не влияют напрямую на данные дочерних компонентов.
- **Применение:** Управление состоянием и передача данных в React-приложениях.

---

## Иммутабельность

- **Определение:** Принцип, согласно которому объекты не изменяются, а при необходимости создаётся новая копия с изменениями.
- **Особенности:** 
  - Облегчает отслеживание изменений и оптимизирует рендеринг.
  - В React изменение состояния должно происходить через создание новых объектов.
- **Применение:** Обновление состояния с помощью методов, создающих новые массивы или объекты (например, `[...state, newItem]`).

---

## Чистая функция (Pure Function)

- **Определение:** Функция, которая при одинаковых входных данных всегда возвращает одинаковый результат и не вызывает побочных эффектов.
- **Особенности:** 
  - Легче тестировать и отлаживать.
  - Обеспечивает предсказуемость поведения.
- **Применение:** Функциональные компоненты и обработчики событий должны по возможности быть чистыми функциями.

---

## Функциональная компонента

- **Определение:** Компонент, представленный в виде обычной функции, принимающей пропсы и возвращающей JSX.
- **Особенности:** 
  - Более простой и лаконичный синтаксис по сравнению с классовыми компонентами.
  - Использует хуки для управления состоянием и жизненным циклом.
- **Применение:** Современный стандарт разработки UI в React.

---

## Хук

- **Определение:** Специальная функция, позволяющая «подключать» состояние и другие возможности React к функциональным компонентам.
- **Особенности:** 
  - Позволяют работать с состоянием (`useState`), побочными эффектами (`useEffect`) и другими аспектами.
  - Правила хуков гарантируют, что их вызов происходит в одинаковом порядке при каждом рендере.
- **Применение:** Реализация логики, ранее доступной только в классовых компонентах.

---

## useState

- **Определение:** Хук для создания и управления локальным состоянием в функциональных компонентах.
- **Особенности:** 
  - Возвращает массив с текущим значением состояния и функцией для его обновления.
  - Обеспечивает повторный рендер компонента при изменении состояния.
- **Применение:** Хранение данных, влияющих на UI, таких как ввод пользователя, переключение тем и т.д.

---

## useEffect

- **Определение:** Хук для выполнения побочных эффектов в функциональных компонентах.
- **Особенности:** 
  - Позволяет выполнять код после рендера компонента.
  - Может выполнять очистку (например, удаление подписок) при размонтировании компонента.
  - Принимает массив зависимостей, что позволяет оптимизировать выполнение эффекта.
- **Применение:** Запросы к API, подписки на события, настройка таймеров и другие операции, не связанные напрямую с рендерингом.
